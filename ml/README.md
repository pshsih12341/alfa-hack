# ML — скоринг заявок

Сервис принимает заявку (ИНН, сумма, срок, цель, залог) и за несколько секунд
возвращает решение: одобрено, предложение другой суммы или срока, нужны выписки
или отказ. Данные о компании сервис берёт сам по ИНН из баз-моков: реестры, БКИ,
ФНС, обороты в Альфе. Описание фич — [`docs/features.md`](docs/features.md).

## Как принимается решение

1. **Стоп-правила** — отказ без модели: организация не действующая (129-ФЗ),
   банкротство компании или собственника (127-ФЗ), перечень Росфинмониторинга (115-ФЗ).
2. **Этап 1, до выписок.** Модель 1 считает PD. PD > 30 % — отказ. Иначе сервис
   перебирает сетку «сумма × срок» (6–36 мес., от 100 000 до 30 000 000 ₽): клетка
   проходит при PD < 5 % и DSCR ≥ 1,25 по потоку, оценённому по выручке.
   Проходит запрошенная клетка — `APPROVED`, другая — `OFFER`, ни одна — `INFO`, нужны выписки.
3. **Этап 2, по выпискам.** Обороты по счёту в Альфе или файлы 1С из других банков.
   Модель 2 добавляет фичи потока (DSCR, волатильность, тренд), порог PD — 15 %.
   Итог: `APPROVED`, `OFFER` или `REJECTED`.

**Ставка** — по корзине PD: 18 / 20 / 22 / 24 %, с залогом 17,5 / 18,5 / 19,5 / 20,5 %
(потери при дефолте 25 % вместо 45 %).

## Модели

WoE-биннинг и логистическая регрессия — своя реализация на NumPy, с p-value
коэффициентов. Отбор фич: IV ≥ 0,02, корреляция WoE ≤ 0,7, знак коэффициента,
p-value ≤ 0,05. Цель и залог включены принудительно.

| | Модель 1 (до выписок) | Модель 2 (по выпискам) |
|---|---|---|
| Фич в модели | 12 из 13 | 14 из 17 |
| Gini train / test OOT | 0,623 / 0,626 | 0,680 / 0,675 |
| KS test OOT | 0,489 | 0,530 |
| PSI скора test OOT | 0,004 | 0,004 |
| Gini на 8 выборках с дрейфом | 0,564–0,645 | 0,617–0,707 |

Данные синтетические, генератор — `alfa_ml.synth`. Обучающая выборка — 20 000 заявок
за 07.2023–12.2024, тестовая out-of-time — 5 000 за 01–06.2025, доля дефолтов около 6 %.
Дрейф — 8 выборок по 5 000: сдвиг состава клиентов и макрошок на 5 / 10 / 20 / 50 %.
Базы-моки для сервиса — отдельный срез из 2000 компаний. Коэффициенты, IV и метрики
по всем выборкам — [`artifacts/model_report.json`](artifacts/model_report.json).

## Запуск

В составе проекта, из корня репозитория:

```bash
docker compose up -d --build
```

Сервис доступен другим контейнерам на `http://ml:8001`, наружу порт не публикуется.
Базы-моки Postgres загружает при первом старте из `mocks/mocks_postgres.sql`.

Отдельно, из папки `ml/` (нужен [uv](https://docs.astral.sh/uv/)):

```bash
uv sync
ML_DATABASE_URL=sqlite:///../mocks/mocks.sqlite uv run uvicorn alfa_ml.service.app:app --port 8001
```

Swagger — http://localhost:8001/docs.

## API

| Метод | Что возвращает |
|---|---|
| `POST /score` | Решение по заявке |
| `GET /companies/{inn}` | Карточка компании: реестр, директор, участники, клиент ли Альфы, известна ли выручка |
| `GET /companies/{inn}/loans` | Действующие кредиты из БКИ — для выбора кредитов к рефинансированию |
| `GET /health` | Статус, подключение к базе, дата среза, версии моделей |

Пример `POST /score`:

```json
{
  "applicationId": "42",
  "inn": "7476595370",
  "creditSum": 2450000,
  "termMonths": 24,
  "purpose": "working_capital",
  "hasCollateral": false,
  "bkiConsent": true
}
```

Необязательные поля:
- `revenueLast12m` — выручка из анкеты, если её нет в источниках;
- `refinanceLoanIds` — кредиты к рефинансированию;
- `useAlfaAccount` и `statements` — для этапа 2. `statements` — до 5 файлов 1С
  в base64, до 5 МБ каждый.

Ответ содержит:
- `decision`, `stage`, `pd`, `rate`, `approved` — решение и условия;
- `offers` — до двух вариантов, `maxByTerm` — максимум суммы на каждом сроке;
- `documentsRequired` — что нужно для этапа 2;
- `clientMessage` — текст клиенту, `reasons` и `stopRules` — для сотрудника банка.

## Команды

Из папки `ml/`, по порядку пересборки:

| Что | Команда |
|---|---|
| Тесты | `uv run pytest` |
| Синтетические выборки и базы-моки | `uv run python -m alfa_ml.synth --out ../mocks/datasets --mocks ../mocks` |
| Сезонность групп ОКВЭД | `uv run python -m alfa_ml.artifacts --train ../mocks/datasets/train` |
| Обучение моделей 1 и 2 | `uv run python -m alfa_ml.models.train --data ../mocks/datasets` |
| Демо-ИНН и файлы выписок к ним | `uv run python -m alfa_ml.scenarios --files ../mocks/statements` |

Генератор детерминирован (`seed` в `config/generator.yaml`): повторный запуск даёт
те же данные.

## Структура

```
ml/
├── src/alfa_ml/
│   ├── synth/        генератор синтетических компаний, оборотов и дефолтов
│   ├── sources/      схема баз-моков, выгрузка в SQLite/Postgres, чтение по ИНН
│   ├── statements/   разбор выписок 1С, категории операций, помесячные обороты
│   ├── features/     фичи моделей 1 и 2
│   ├── models/       WoE-биннинг, скоркарта, обучение
│   ├── decision/     стоп-правила, решения этапов 1 и 2
│   ├── service/      FastAPI-сервис
│   ├── metrics.py    Gini, KS, PSI
│   └── scenarios.py  подбор демо-ИНН
├── config/
│   ├── rules.yaml        стоп-правила и тексты отказов
│   ├── scoring.yaml      пороги решения, ставки, сетка сумм и сроков
│   ├── training.yaml     параметры биннинга и отбора фич
│   └── generator.yaml    параметры синтетики
├── artifacts/        model1.json, model2.json, seasonality.json, model_report.json
├── docs/features.md  описание фич
└── tests/
```

Все пороги — в `config/`, не в коде.

## Переменные окружения

| Переменная | По умолчанию | Описание |
|---|---|---|
| `ML_DATABASE_URL` | `postgresql://credit_kiosk:credit_kiosk@localhost:5432/mocks` | Базы-моки: Postgres или `sqlite:///путь` |
| `ML_AS_OF` | дата среза из базы | Дата, на которую считаются фичи |
| `ML_CORS_ORIGINS` | пусто, CORS закрыт | Источники для запросов из браузера, через запятую |
| `ALFA_ML_ARTIFACTS_DIR` | `ml/artifacts` | Где лежат модели |
